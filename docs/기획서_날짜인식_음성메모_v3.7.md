# 기획서 — 날짜 인식 음성메모 → 해당 날짜 Today Action Item 자동 라우팅 (v3.7.0)

작성일: 2026-06-28
대상 저장소: `meeting-recording-mobile`(앱) + `Obsidian-Automation`(자동화)

## 1. 목표

음성 메모에 날짜 단서가 포함되면, 그 날짜의 데일리노트 `## ✅ Action Items`에 자동 배치한다.

예시:
- "다음주 화요일에 상임위 참석해야 하니까 일정에 넣어줘" → 다음주 화요일 노트
- "7월 3일 9시 서원CC 골프부킹 해야 돼" → 7/3 노트
- "7월 5일 주주간담회 참석을 위해 7월 2일까지 자료 작성해야 하니까 7월 2일 자료 작성 알려줘" → 7/2 노트

날짜 단서가 없는 일반 메모는 기존 동작(당일 노트 있으면 오늘, 없으면 아침/저녁 동기화 기본값)을 유지한다.

## 2. 핵심 원칙

> **날짜 해석은 "녹음 시점"에 AI가 절대 날짜로 1회 변환하고, 라우팅은 자동화가 날짜별로 분배한다.**

- "다음주 화요일" 같은 상대 표현은 녹음한 날을 기준으로 풀어야 정확함 → 앱(요약 단계)에서 해석.
- 자동화는 나중에 실행되므로 상대 표현을 그대로 받으면 어긋남 → 파일에는 **절대 날짜만** 저장.

## 3. 역할 분담 (확정)

| 항목 유형 | 처리 |
|---|---|
| 날짜 있는 항목 | 앱은 절대 날짜만 frontmatter에 기록 → `00_Inbox/voice_memos/` 저장 → **자동화가 해당 날짜 데일리노트로 라우팅**(다음 sync 때, `get_or_create`로 미래 노트도 안전 생성) |
| 날짜 없는 항목 | **기존 동작 유지** — 당일 노트 있으면 즉시 오늘 주입, 없으면 inbox → 자동화 morning=오늘/evening=내일 |

혼합 메모(날짜 항목 + 무날짜 항목): 무날짜 항목은 오늘 노트에 즉시 주입, 날짜 항목은 inbox에 남겨 자동화가 라우팅. **즉시 주입한 항목은 inbox 파일에서 제외**하여 중복 주입 방지.

## 4. 데이터 포맷 (앱이 생성하는 .md)

```markdown
---
created: 2026-06-28 14:30
type: voice_memo
action_items:
  - date: "2026-07-07"     # "다음주 화요일" → AI가 절대 날짜로 변환
    text: "상임위 참석"
  - date: "2026-07-03"
    text: "서원CC 골프부킹 (09:00)"
  - date: "2026-07-02"     # "7/5 간담회 대비 7/2까지" → 리마인드일 = 7/2
    text: "주주간담회 자료 작성 (7/5 간담회 대비)"
  - date: null             # 날짜 없는 일반 메모
    text: "ㅇㅇ건 검토 필요"
---

## 요약
- 📅 2026-07-07 — 상임위 참석
- 📅 2026-07-03 — 서원CC 골프부킹 (09:00)
- 📅 2026-07-02 — 주주간담회 자료 작성 (7/5 간담회 대비)
- ㅇㅇ건 검토 필요

## STT 원문
...
```

- `action_items`(frontmatter): 자동화가 라우팅에 사용 (PyYAML 파싱)
- `## 요약`: 사람이 읽는 용도 + 구버전/폴백 호환
- 날짜는 항상 절대값(상대 표현은 앱에서 이미 해석 완료)

## 5. 구현 내역 (Phase 1 — 완료)

### 앱 (`meeting-recording-mobile`)

1. `service/GeminiService.kt` — `SUMMARY_VOICE_MEMO` 프롬프트를 구조화 JSON 출력으로 교체.
   - `{today}`(요일 포함 기준 날짜) 제공 → 상대 표현 절대 날짜 변환.
   - `"N일까지"` 마감 작업은 마감일을 date로.
   - 출력: `{"summary":"...","action_items":[{"date":"YYYY-MM-DD|null","text":"..."}]}`
2. `service/GeminiService.kt` / `service/ClaudeService.kt` — `summarize()`에 `{today}` 치환 추가(두 엔진 공용 프롬프트).
3. `viewmodel/RecordingViewModel.kt`
   - `parseVoiceMemoJson()` — JSON 파싱(코드펜스/잡텍스트 방어), 실패 시 요약/원문을 date=null 단일 항목으로 폴백.
   - `runVoiceMemo()` — `action_items` frontmatter + `## 요약` 작성, 날짜 인식 라우팅(오늘/무날짜 즉시 주입, 그 외 inbox).
   - `injectIntoDailyNoteActionItems()` — 항목 단위 멱등 마커(`...#i`)로 다중 항목 주입.
   - `MemoItem` 데이터 클래스, `renderMemoItemLine()`, `yamlActionItems()` 추가.

### 자동화 (`Obsidian-Automation` / `_automation/modules/voice_memo_inject.py`)

1. `_extract_action_items()` — frontmatter `action_items`(date 포함) 우선 파싱, 없으면 기존 `## 요약` 폴백(전부 date=null).
2. `_parse_frontmatter()`, `_normalize_date()` — YAML frontmatter 파싱 + 날짜 정규화(따옴표 없는 date 객체도 처리).
3. `execute()` — 항목을 **날짜별로 그룹핑**해 각 날짜 데일리노트에 주입. date 없으면 mode 기본값(morning=오늘/evening=내일).
4. 명시 날짜는 mode를 무시하고 그 날짜로 (저녁 sync여도 오늘 건은 오늘로).

## 6. 불변 보장 / 엣지 케이스

- 날짜는 앱(녹음 시점)에서만 해석 → 자동화는 절대 날짜만 사용(상대 표현 어긋남 없음).
- JSON/날짜 해석 실패 → date=null 폴백 → 기존과 동일 동작(안전).
- 미래 날짜 항목은 다음 sync 실행 시점에 미래 노트(템플릿대로 생성)로 들어감(즉시 아님).
- dedup: 파일 단위 `synced`(한 번에 전 항목 라우팅) + 앱 즉시 주입은 항목 단위 마커.

## 7. 후속 (Phase 2 후보)

- 과거 날짜(이미 지난 날) 항목의 오늘 클램프 옵션.
- 미래 날짜 항목의 즉시 반영(앱이 미래 노트 직접 생성) — 현재는 자동화 라우팅으로 결정됨.
